## Правила изменений от ИИ

- Все изменения, предлагаемые ИИ, сначала оформлять как патч и показывать пользователю diff до применения.
- Не изменять файлы напрямую без явного согласия пользователя после просмотра diff.
- Патч должен быть минимальным и содержать только изменения, необходимые для задачи.
- Не включать в патч несвязанные исправления, автоматическое форматирование или изменения стиля.
- После согласования применять патч отдельным логическим изменением.
- Если создаётся коммит, использовать понятное краткое сообщение, описывающее результат изменения.
- Несвязанные изменения оформлять отдельными коммитами, а не объединять в один большой коммит.
- При необходимости добавлять к коммиту комментарий с причиной изменения, важными решениями, ограничениями и способом проверки.
- Не выполнять коммит автоматически без явного разрешения пользователя.
- После применения согласованного патча показывать итоговый diff и результат узкой проверки, относящейся к изменению.

## Термины

Патч — набор изменений в формате diff, который можно просмотреть и применить. Коммит — сохранённая в Git версия изменений. Патч может соответствовать одному коммиту или нескольким логически разделённым коммитам; перед применением всегда сначала показывать diff.
